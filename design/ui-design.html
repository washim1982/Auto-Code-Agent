Auto-Code-Agent · Interface design

Desktop & CLI layout

Two front-ends over one daemon. State reads as temperature — cold queued, warm running, hot failed — so a twenty-node run resolves at a glance before a single label is read.

The heat ramp

Node state is the single most-scanned value in the product, so it is encoded three ways at once: hue, glyph, and border weight. The ramp runs cold to hot, and urgency rises with temperature — you look at the warm end first.

○ Queued#6B7C8C

Blocked or waiting on a lock. Inert, dimmed to 72%.

✓ Done#7FA05F

Passed gates and review. Deliberately quiet — finished work recedes.

⚠ Waiting on you#D9B24C

Approval or escalation. The only state that pulses in the CLI.

▶ Running#E07B45

Also the interactive accent. Live work and clickable share one hue.

✗ Failed#D1525F

Gate or permanent failure. Also marks untrusted tool output.

Ramp doubles as the timeline event legend and the CLI palette

Rules both surfaces obey

Untrusted content is visibly fenced

Anything from a tool, file, or network carries a crimson rule and an untrusted tag wherever it renders. Users can see the trust boundary the guard enforces.

Cancel is always one key away

esc in the CLI, a persistent control in the status strip. Cancelling checkpoints the run — it never discards work.

Nothing interactive-only

Every TUI action has a flag equivalent, and --json emits the same event stream the desktop consumes.

Irreversible needs a fresh yes

Push, deploy, publish, and outbound POST prompt at execution time in wheat, regardless of plan-level approval.

Chat is the spine. A run is not a separate mode — it is something a conversation escalates into, so Chat and Run graph are two representations of one session, swapped by a toggle in the panel header. The file tree is a persistent left panel across both.
